# Pilot Logs

Welcome to the accountability corner. Every flight, rehearsal, MSP playback jam, or OBS dry run gets logged here. Treat it like a band diary crossed with an aviation incident report—the details keep us safe and make future sets better.

## How to use this folder

1. Copy `TEMPLATE.md` → rename with timestamp + context (e.g. `2025-10-03_testflight.md`).
2. Fill in **before/after** sections immediately. Include:
   - Airframe + battery notes (cycles, issues, firmware changes)
   - Environment (venue, RF noise, audience proximity)
   - Audio chain (interface, limiter settings, SPL readings)
   - Incidents, near-misses, or aha moments
3. Commit the log alongside any config or patch tweaks you made that day.

## Why bother?

- **Safety trail** — if a prop nicks someone or RSSI tanks, you’ve got data to diagnose and improve.
- **Sound design memory** — note which CC curves or Rack modules worked so you can recreate that crunchy drone six months later.
- **Teaching fodder** — students can read past logs to understand failure modes before they fly.

## Bonus habits

- Attach photos/schematics in the same directory when you rewire hardware.
- If you measure SPL, log the meter brand + weighting (A/C) so the data means something later.
- For multi-pilot crews, initial each entry and list who was on sticks vs. on the mixer.
